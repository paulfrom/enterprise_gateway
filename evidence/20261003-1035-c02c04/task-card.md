## C-02 可信身份绑定保护域与原始 ACL 契约

- 核心目标：
  建立类型化、不可变的可信身份上下文（`TrustedIdentity`），实现企业身份对保护域（Protection Domain）、租户（Tenant ID）、角色集合（Roles）、授权用途（Purposes）及原始 ACL 的强绑定。
- 安全铁律：
  **严禁从客户端 HTTP Header（如 `X-User-Id`、`X-Tenant-Id`、`X-Domain`、`X-Roles`、`X-Original-ACL` 等）直接获取或变更身份信任**。
- 正反例覆盖：
  1. 正例：受信任认证上下文（如由内部 mTLS / 受信鉴权中间件颁发）合法解析并绑定租户、域与原始 ACL；在域内、ACL 范围内且目的匹配的操作获准。
  2. 越权反例：客户端请求试图通过 Header 伪造或篡改身份、域或 ACL，一律强制阻断或忽略；
  3. 跨域反例：跨租户、跨域访问判定为非法越权（`ScopeError`），强制拒绝；
  4. 权限与目的反例：主体不在来源 ACL 内、缺少必需角色、或请求目的超出授权用途，一律拒绝；
  5. 不完整反例：空/空白主体 ID、空租户、空域、非枚举角色或非法时间戳一律拒绝，断链无敏感信息回显。

## C-04 精确静态内容免检边界契约

- 核心目标：
  在不降低检测安全性的前提下，对已知、预审批且完全静态的内容（如标准 System Prompt、固定免责声明模版）提供**精确边界**的免检支持。
- 安全铁律：
  **只有内容与边界均与注册模版 100% 精确一致时才可免检；动态变量、拼接内容永远不得继承免检资格；客户端不得自声明免检**。
- 正反例覆盖：
  1. 正例：内容与边界均与受信任清单中的模版完全逐字符匹配（含空白与标点），判定为 `EXEMPT`，检测器 Spy 不被触发；
  2. 改单字反例：修改单个文字、增删空格、大小写微调，均立即失效，判定为 `NOT_EXEMPT`，必须触发全量检测；
  3. 混入变量反例：静态模版中插入占位符或动态变量，均不得继承免检，必须触发全量检测；
  4. 不可分离组合反例：静态提示词与动态用户输入混合在同一字段且无严格契约边界时，整体强制判定为 `NOT_EXEMPT`；
  5. 伪造与自称反例：客户端自声明免检或指定未注册模版 ID，一律拒绝或忽略，不得绕过检测。
