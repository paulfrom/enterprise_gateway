## C-05 请求固定完整版本：manifest 与加载句柄

- 核心目标：
  建立统一配置/模型/策略包清单（`PackageManifest`）与请求版本生命周期句柄（`RequestVersionHandle`）。确保单次请求在生命周期内绑定恒定不变的包哈希，热更新或蓝绿切换不产生版本混用；坏包拒载并提供回滚机制。
- 场景与断言：
  1. 正例：合法包 Manifest（包含 policy、protocol、exemption 等组件哈希）成功加载并验证根哈希；请求生命周期内 `package_hash` 恒定不变。
  2. 篡改与损坏反例：组件内容被篡改、SHA-256 不匹配、缺少关键文件或 JSON 语法损坏，一律拒绝加载（`CorruptedPackageError`）。
  3. 处理中更新反例：当全局激活新版本包时，正在处理中的请求句柄不受影响，仍保持旧版本的单版本视图；新请求加载新版本视图。
  4. 跨请求混用反例：严禁跨请求混用不同版本的配置、协议或策略。

## C-06 固定独立质量口径：划分审计与门槛契约

- 核心目标：
  建立测试集独立性划分审计（`DatasetSplitAudit`）与严格的敏感信息检测质量评价口径契约（`QualityEvaluator`）。
- 场景与断言：
  1. 正例：评测数据集与训练集/开发集严格无交集（Disjointness check passed）；可追溯样本 ID、分母、标签与门槛版本；在合成验证集上正确计算准确率、召回率、F1 及 $3/n$ 置信区间上界。
  2. 样本污染/交叠反例：测试样本与训练集或规则集存在 ID 或内容重叠时，划分审计强制拒绝通过。
  3. 盲测选型反例：禁止在评测独立集上迭代优化规则或筛选模型（反向数据泄漏）。
  4. 秘密放行硬失败反例：测试集中任何已标注的 SECRET 类别漏检（泄漏），判定为整体验收一票否决（Hard Failure），不可通过高召回率平均抵扣。
  5. 未授权门槛反例：未取得正式批准的生产门槛时，质量报告明确标注为 `UNAPPROVED_THRESHOLDS`，不得宣称生产达标。
