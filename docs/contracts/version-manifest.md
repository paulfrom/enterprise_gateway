# 请求固定完整版本契约（C-05）

版本：1.0.0（2026-10-03，固定契约）

## 1. 契约目标与安全边界

本契约用于保证网关在处理大模型调用与知识沉淀的单次业务请求时，**请求生命周期内必须绑定唯一的、不可变的配置/模型/策略包哈希（`package_hash`）**。

### 安全铁律

1. **单请求内版本绝对一致**：
   单次业务请求在进入网关时通过 `RequestVersionHandle` 锁定版本；在该请求的整个生命周期中（包含身份校验、政策解析、协议转换、敏感检测与响应脱敏恢复），引用的政策、词典、模版和模型白名单必须保持单一包哈希，严禁跨请求混用不同版本的组件。
2. **热更新不破坏在途请求**：
   当后台执行版本切换（蓝绿切换或热配置生效）时，新请求将绑定到新版本包，而已在处理中的在途请求继续持有其原本的不可变句柄，直到该请求处理结束。
3. **坏包拒载与原子切换**：
   任何组件哈希不匹配、文件缺失、内容损坏或格式非法的包，在加载检验阶段立即被强制拒绝（`CORRUPTED_PACKAGE`）。损坏的包绝不能被激活，当前运行版本保持不变（保证不发生损坏扩散或降级为混合状态）。

## 2. 核心结构

- `ComponentEntry`: 包含组件名称、组件版本及内容 SHA-256 摘要；
- `PackageManifest`: 包含 `manifest_id`、`version`、创建时间、组件字典及确定的根哈希 `package_hash`；
- `RequestVersionHandle`: 冻结的不可变句柄，记录 `request_id`、`package_hash`、`version` 与绑定时间戳；
- `VersionManager`: 管理当前激活版本，提供请求句柄绑定与安全原子切换。
