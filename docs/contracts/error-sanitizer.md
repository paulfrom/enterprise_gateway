# 上游错误净化契约（P-13）

版本：1.0.0（2026-10-03，固定契约）

## 1. 契约目标与安全边界

当模型供应商、上游微服务或网关层在调用过程中返回 4xx/5xx 错误时，其返回内容极可能包含：
- 用户的原始提示词片段（例如“Invalid token in prompt: <敏感词>”）；
- 内部 IP 地址、端口或 DNS 拓扑；
- 供应商 API Key 或内部认证令牌；
- 数据库或框架运行堆栈信息。

### 安全铁律

1. **原始错误正文 100% 丢弃**：
   上游返回的 `upstream_raw_body` 在进入网关净化器后被完全丢弃，不进行任何形式的拼接、回显或日志泄漏。
2. **必要状态码保真映射**：
   透传真实 HTTP 状态码（如 429 限流、502 错误网关、503 服务不可用、504 超时等），便于客户端执行合规的重试策略。
3. **白名单响应头透传**：
   仅允许与流量退避直接相关的响应头（如 `Retry-After`）安全传递，其余所有内部头信息均被剥离。
4. **统一标准化安全响应体**：
   将错误收敛为受控的错误码（如 `UPSTREAM_RATE_LIMITED`、`UPSTREAM_SERVICE_UNAVAILABLE`）与中立安全的本地化提示。
5. **Canary 强验证**：
   通过 Canary 测试验证：即使上游注入真实机密或私钥字符串，下游客户端收到的响应体中绝对为 0 泄漏。
