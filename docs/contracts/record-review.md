# 单记录审计审阅契约

`audit.record_review.RecordReviewService` 是内部审计组件。采用 [Microsoft Entra PIM](https://learn.microsoft.com/en-us/entra/id-governance/privileged-identity-management/pim-configure) 的按需、限时、审批访问模式，结合本项目的双人职责分离要求。它直接调用既有 `infra.envelope_crypto.decrypt_record`；不实现另一个加密格式或数据库。

## 输入与信任边界

装配由受信服务提供已有 `EnterpriseAuthenticator`、`KmsProvider`、受控账本目录和服务时钟。所有请求、批准及读取逐次验证企业凭据；身份、角色、域、租户与用途来自认证上下文。客户端自报内部身份头、伪凭据、失效身份均拒绝。组件没有公开 HTTP 路由。

`request(headers, record, tenant_id=..., purpose="audit-review", expires_at=...)` 的 `record` 与 `tenant_id` 必须由受信审计存储解析现存加密证据及相应租户元数据后提供，不能直接从客户端请求体取得。既有信封 AAD 含域、记录、加密用途和格式版本，不含租户；因此调用方必须保持审计记录与租户元数据的一致可信关联。知识证据与审计证据的存储/密钥权限分离仍由装配保证，禁止把知识域任意密文交给审阅组件。

工单固定请求者、租户、域、单记录 ID、整份规范化密文 SHA-256、原加密用途、审阅用途、签发及过期时间。密文摘要用于精确绑定随机密文，不能用于证明业务授权。工单期限必须在申请身份期限内，读取采用 `issued_at <= now < expires_at`。没有隐含的永久权限或默认批准。

## 权限矩阵

| 操作 | 必需身份与范围 | 允许行为 | 拒绝行为 |
|---|---|---|---|
| 申请 | `audit-reader`，`audit-review` 用途，同租户同域 | 为一份现存加密审计记录生成限时工单 | 批量记录、错租户/域、错用途、无效时限 |
| 安全批准 | `audit-security-approver`，同租户同域与审阅用途 | 写入安全审批 | 请求者自批、角色不符、过期/消费工单 |
| 数据批准 | `audit-data-approver`，同租户同域与审阅用途 | 写入数据审批 | 与安全审批同人、重复角色、请求者自批 |
| 读取 | 申请人当前凭据、`audit-reader`、审阅用途 | 两名不同且非申请人的有效审批后精准解密一次 | 别的员工、密文替换、缺审批、到期、重放 |

即使一人拥有两种审批角色，也不能同时填两个审批槽。审批身份在批准时验证，读取时检查审批时间和身份到期时间；企业 IAM 的即时撤权、MFA、组织职责分离、生产 KMS 权限须由生产接入另行验证。工单 ID 仅是定位句柄，不能代替认证。

## 持久性与故障

工单及审批采用已有 `durable_commit`，每次行为事件使用独立文件。事件仅含固定操作/结果码、身份范围、时间和工单句柄摘要，不含证据正文或凭据。

每工单以原子创建目录互斥，覆盖不同服务实例及进程。合法读取先可靠记录访问尝试，可靠写入一次性消费标记，再执行真实 AEAD 解密，可靠记录访问结果后才返回明文。解密完成时及最终审计、互斥释放完成后均重新认证申请人、检查工单与全部审批身份有效期；KMS或审计耗时跨过截止时没有明文返回，消费标记保留。`accessed`表示受控解密和结果留证完成，不保证调用方已收到原文，最后时限失效可随后产生拒绝事件。KMS/认证失败仍消费已经开始的工单；访问审计失败绝不释放明文。消费标记存在即拒绝，空文件也不视为可恢复。并发最多释放一份明文。

服务崩溃遗留锁会继续拒绝。受控恢复须确认没有活跃进程、保留已记录状态，判断访问结果未知；不自动移除锁或重开工单。底层 Windows 目录 fsync 的限制继承既有写入契约，生产卷持久性另行验证。无法写审计时返回 `AUDIT_WRITE_FAILED` 并拒绝；存储本身不可用时不伪称拒绝日志已成功落盘。

读取接口一次仅返回指定记录 `bytes`，没有列举、批量读取或原文导出方法。返回的获准原文属于企业审计可信区，不能再写普通日志或交外部模型。

## 可证明的范围

测试使用真实企业凭据匹配、真实 AES-GCM、真实持久文件以及现有 `EvidenceGate` 生成的加密留证；KEK、身份和正文均明确为合成材料。覆盖不同线程/进程竞争、重启重放、时间与职责分离、AAD篡改、KMS/写盘故障。组件验证不代表真实企业 IAM/KMS 或生产卷验收，不启动真实业务资料审阅或批量导出。
