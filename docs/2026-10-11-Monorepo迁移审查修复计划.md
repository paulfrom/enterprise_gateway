# Monorepo 迁移审查修复计划

本计划定义迁移审查后的实现修复与验收要求，以当前 Linux 开发机为执行环境。它是独立的技术实施计划，不依赖不存在的父目录 WBS、里程碑或接续文件，不记录执行进度和运行证据。

## 环境与范围

- 项目由 Windows 迁移至当前机器；仓库根为 `/home/paul/project/enterprise_gateway`。
- 开发环境使用 HTTP，不要求 HTTPS、证书或生产 TLS 配置。移除无效的 443 监听、发布与提示，不增加强制 HTTPS 跳转。
- 数据库、模型、密钥、运行状态、操作制品及文件均复用本机现有资源。PostgreSQL 使用本机 5433 端口，不新建替代数据库服务、不依赖原 Windows 路径或远端基础设施。
- 已核对 `apps/backend/.env.test` 中应用与管理连接均指向 `127.0.0.1:5433`。此文件是被忽略的受控配置，计划和报告不得包含密码或完整 DSN。
- 当前工作区已有 `apps/admin-web/Dockerfile`、`deploy/compose.yaml` 修改和 `deploy/nginx/` 新文件；在这些改动基础上修复，不重置、覆盖或丢弃用户工作。
- 本轮交付迁移后的可用登录和请求历史流程及工程门禁，不扩展为另一份管理员计划中尚未交付的全部管理功能；既有管理 API 不得因缩小本轮范围被删除。
- 不提交或推送 Git，不删除既有数据库、schema、角色、数据卷、模型、密钥或管理员状态。临时验证产物写入 `/tmp` 或被忽略的本地目录。

代码发现遵循图工具优先；配置、脚本、文档可直接读取。以实际代码和本机资源为依据，旧计划中的 Windows、父目录材料和生产验收描述不作为本轮前置。

## 修复顺序与实现要求

### 本机资源绑定与 HTTP 入口

涉及 `deploy/compose.yaml`、`deploy/nginx/admin.conf`、两个 Dockerfile、`.runtime_state/local/up.sh` 及后端启动配置。

1. 只读核对现有本地启动脚本、文件挂载、模型目录、状态目录及数据库连接引用，输出脱敏的路径和用途说明。不得打印秘密正文。
2. 前端默认仅监听、发布 HTTP 端口，默认绑定地址采用本机开发约定；移除前端 443 和无效 HTTPS 环境变量。保留后端已有显式传输配置能力，不顺便删除无关实现。
3. 原生进程连接 `127.0.0.1:5433`；容器不得把自身的 `127.0.0.1` 当作宿主数据库。核实本机监听地址和已有可用访问路径，为容器提供明确宿主机地址映射及独立受控 DSN 文件。
4. 优先复用现有可用配置，不自动把 PG 监听扩大到公网，不修改已有账号权限以绕过校验；连接不可达时报告实际限制，不改用空库。
5. 核实 state/admin 的实际持久化选择。若保留独立管理员卷，镜像先创建 `/app/state/admin` 并赋予运行 UID 65532 权限；已有卷的权限只对明确管理员目录实施最小修复，不递归修改所有数据。
6. 管理员已初始化时复用状态。禁止重置账号、密码和会话以获得成功案例；未初始化时按已有工具显式初始化并保护凭据，不写入前端源码或报告。

验收：HTTP 入口可访问；没有无效 443 暴露；本机 PG 5433 连通；新建隔离状态目录可写；既有状态与数据绑定未被替换。

### Docker 构建上下文与启动入口

涉及 `apps/admin-web/Dockerfile.dockerignore`、前端 Dockerfile、`rebuild_and_run.sh`、README。

1. 修复根 context 默认拒绝白名单：仅允许根 npm 清单、Node 版本、管理契约、前端必要源码与配置、Nginx 配置。父目录例外不得重新引入 `apps/backend` 或任意未知子目录。
2. 前端秘密、模型、运行状态、环境配置、依赖、产物和日志均不进入 context。目录层级的例外规则使用实际 Docker 构建验证，不仅做文本判断。
3. 在临时 context 中放置合成 canary，验证后端和前端敏感/未知路径均被排除、必要构建输入可达。不要为验证复制真实秘密。
4. 启动脚本使用实际服务名；移除先 `down` 再启动错误 `gateway` 服务的流程。启动前校验本地配置，采用有范围的 `up -d` 更新，不使用 `down -v`。
5. 修正健康/就绪判断、管理员入口端口、容器日志命令及 README 的旧服务名。没有本地私有脚本时，标准启动路径也必须完整可用。

验收：合成 canary 测试通过；前后端镜像从规定 context 构建；配置错误时不先停止现有服务；标准与现有本地入口定位同一套资源。

### 同源代理与 API 错误

涉及 `apps/admin-web/vite.config.ts`、Nginx 配置及相关后端认证回归。

1. Vite 代理保留浏览器原始 Host，避免 `changeOrigin` 与原始 Origin 冲突。
2. Nginx 转发带端口的原始 Host，配合明确的 Host/Origin 校验；不得删除后端同源验证或放宽为任意 Origin。
3. HTTP 登录签发 HttpOnly、SameSite Cookie，按现有 HTTP 传输契约工作；CSRF 校验保持有效。
4. 管理 API 和模型 API 的代理自产 413、502、504 返回规定 JSON 错误和正确状态码。保持后端错误透传，不用 SPA HTML 或 HTTP 200 掩盖失败。
5. 保持旧历史入口及内部健康/就绪探针不通过前端公开；未知 API 与缺失资源不落入 SPA HTML。

验收：Vite 非默认端口和 Nginx 显式端口同源登录成功；跨域和缺失/错误 CSRF 失败；超限及代理故障返回 JSON；模型流式响应不因修复启用缓冲。

### TypeScript、OpenAPI 与生成类型

涉及前端 package/tsconfig、后端管理路由、导出工具、`contracts/admin.openapi.json` 和生成类型。

1. `typecheck` 实际检查 app 与 node 配置；`build` 在类型检查失败时退出。选择显式 `-p` 检查或正确的项目引用构建，不保留空项目假通过。
2. 临时副本加入可达源码类型错误，确认 typecheck 与 build 都非零退出；移除 canary 后实际工程通过。
3. 为实际管理路由补齐请求体、查询参数、成功响应和共享错误契约。优先复用现有领域类型，不增加第二套手写前端业务定义。
4. 保留当前重复 JSON 键、未知字段及认证/释放前检查等行为。增加 OpenAPI 元数据不能引入宽松解析或改变真实错误语义。
5. 明确异步 202、参数不合法、未认证、CSRF/同源失败及依赖不可用等状态。不得把 FastAPI 默认验证错误当作应用真实错误体。
6. 从后端重新导出契约，再生成 `schema.d.ts`；两个漂移检查独立有效。根检查同时执行后端 OpenAPI `--check` 与前端 `check:api`。
7. 增加有意义的契约断言，证明登录请求、历史查询及关键响应结构已声明；不使用“没有空 schema”一类过宽断言误伤合法无正文响应。

验收：类型错误 canary 被拦截；实际工程检查通过；登录/历史类型可用于薄客户端；契约及生成类型无漂移。

### React 登录和请求历史贯通

涉及 `apps/admin-web/src`、浏览器测试、后端旧页面路由/资源及相关打包测试。

1. 在现有 React、Ant Design、React Router、TanStack Query 结构中实现 `/login`、`/admin`、`/admin/requests`。复用现有设计，不进行无关视觉重构。
2. 使用真实 `login/session/logout` API，建立受保护路由与会话恢复。凭据和 CSRF token 不进入浏览器持久存储，服务器会话决定权限。
3. 薄客户端从生成契约获得请求/响应类型，统一 Cookie、CSRF、取消和 JSON 错误处理；不新增通用响应包装。
4. 历史列表支持后端已有筛选、游标分页与详情；展示四阶段可用正文、JSON/SSE 解释和复制，内容作为文本渲染。无独立历史查询 Key，无原文二次解锁。
5. 实现未认证、错误凭据、依赖未就绪、无数据、加载失败及会话过期的真实状态。退出/401 后清空查询缓存和正文，取消或忽略迟到响应。
6. 替换固定“网关就绪”文本，状态来自可用的真实管理接口；不可用时明确显示原因。
7. React 功能及验收可用后删除后端旧 `gateway/web` 资源和 FileResponse 页面服务，更新预览、测试和打包契约。前端拥有页面入口，后端仍逐请求保护数据 API；不得保留双页面实现。
8. 增加可执行 `test:e2e`，使用本机后端、PG 5433 与隔离合成历史记录；不得依赖真实供应商调用或改写既有历史。

验收：真实浏览器覆盖正确/错误登录、未登录直达、刷新恢复、分页筛选、详情及复制、恶意 HTML 文本、会话失效、退出与迟到响应。源码和 wheel 不再携带旧页面；已有业务 API 权限不下降。

### 本机 PG 权限和 worker

涉及现有数据库准备工具、知识配置、受控连接文件和必要权限测试。

1. 重现 worker 的 forced-RLS/独立所有者校验失败，核对实际绑定 schema、表所有者、FORCE RLS 和运行角色。不能只依据旧日志修改 DDL。
2. 优先修复错误连接、schema 或角色绑定。需要新结构时在现有本机 PG 中建立明确的新 namespace 和受限角色，使用现有幂等工具；不替换数据库，不搬迁或清空旧数据。
3. 不授予 worker 超级用户、BYPASSRLS、对象所有权或管理角色，不关闭 RLS，不删除启动安全校验。
4. 运行正例和越权反例，证明 worker 能执行受限操作，不能伪造 admin 获取管理权限。只接受测试合成数据。
5. 历史集成测试显式配置 `GATEWAY_HISTORY_PG_CONFIG`，连接本机 5433；使用独立随机测试 namespace，并仅清理本轮创建的对象。

验收：worker 使用正确本机资源持续运行，无配置拒绝重启；受限角色正反测试通过；既有 schema、数据与角色未被破坏。

### 回归失败、检查入口与 CI

2. 单独复现审查发现的流式保护、上游错误和断连测试失败。核对 compatible/strict 模式的实际契约；错误模式绑定应修正，真实保护缺陷应修代码。禁止删除断言、改期望值或放宽零泄露保护来制造通过。
3. 修复测试阻塞的具体原因或为外部等待设置合理期限；不要用整组跳过替代定位。多进程 runner 必须有 `__main__` 保护，记录准确的 test ID，避免重复补跑。
4. Linux 提供可用的检查入口，可保留 PowerShell 支持；两者执行相同必要检查、使用明确 cwd、传播失败退出码，不保留旧路径 fallback。
5. CI 使用 pyproject 支持且实际验证的 Python 版本、冻结 uv 依赖和正确 backend cwd，安装根 npm workspace 依赖，执行前后端、契约与构建检查。不要保留查找根 requirements.txt 的旧逻辑。
6. CI 数据库只使用 runner 隔离资源，测试端口保持 5433，与本机 PG 的配置契约一致；不得连接开发机真实数据库或远端生产资源。开发机不额外启动第二个 PG 服务。
7. 先跑受影响的确定性测试和浏览器流程，通过后只做一次必要的完整回归。单轮设置合理上限；超时定位实际 test ID 后局部复验，不重新启动全部已通过测试。

验收：受影响用例和必要全量回归有明确结果；不把 skip、超时、夹具缺失写成通过；CI 声明与本地入口一致。
