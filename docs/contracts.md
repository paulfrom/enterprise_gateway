# 企业隐私网关契约与规范体系

本文档定义企业隐私网关的核心契约体系与安全边界规范。字段级数据模型直接由 `enterprise_gateway` 相应模块中的强类型 Pydantic Schema（`extra="forbid", strict=True`）定义并保证单一真实来源。

---

## 1. 分级外发政策契约 (Policy Contract)

* **受信来源边界**：政策配置仅接受受信上下文对象或受管配置文件传入（`load_policy`），客户端请求体、请求头或自报"获准"均非政策来源。
* **分级映射规则**：
  * `approved_external`：获准外发，允许进入隐私检测与脱敏处理流水线。
  * `secret` / `local_only`：高敏或不可外发内容，直接阻断，绝不到达外发环节。
  * 未知或缺失分类：直接拒绝，禁止隐式放行。
* **严格解析**：未知字段、重复 JSON Key、非标准常量（`NaN`/`Infinity`）、超深嵌套均触发受控异常拒绝。

---

## 2. 可信身份与保护域契约 (Identity Contract)

* **不可变身份绑定**：每个处理请求必须绑定不可变的受信身份（`TrustedIdentity`），明确限定 `caller_id`、`tenant_id`、`domain_id`（保护域）、`role`、`purposes`（需包含 `model-query`）及数据访问权限 `scopes`，并严格处于时间有效期内（`authenticated_at <= now <= expires_at`）。
* **防伪造原则**：外部客户端请求头自称的租户或保护域一律无效，身份元数据仅允许由网关上游受信任的鉴权反向代理/内部网关适配注入。
* **身份与原始 ACL 分离**：网关前置统一入口，所有经过网关的输入默认可采集，缺客户端来源 ID 或原始 ACL 不作为采集拒绝前提。客户端传入的可信原始 ACL（若存在）予以保留，仅用于下游知识资产的读取与发布授权，不与模型外发权限混淆。
* **跨域强阻断**：严禁请求跨越已分配的保护域访问数据或应用非本域隐私政策。

---

## 3. 协议字段策略与模型绑定契约 (Protocol Contracts)

支持 **OpenAI Chat Completions** 与 **Anthropic Claude Messages** 两种标准交互协议：

* **逐字段强校验**：请求 JSON 仅允许协议白名单声明的必要字段（如 `model`, `messages`, `temperature`, `max_tokens`, `stop`, `stop_sequences` 等），未声明字段、非法类型或多余嵌套直接整单拒绝。
* **去品牌硬编码与绑定模型集合**：请求与响应模型从硬编码品牌常量解耦，由本请求绑定渠道与完整版本包声明的有限模型集合（`allowed_models`）进行严格校验与映射。
* **全字符串字段分级检测**：所有角色（`system`, `user`, `assistant` 等）消息文本以及协议允许的字符串结构字段（如 DeepSeek 的 `stop`、Claude 的 `stop_sequences`）均统一视为待检测输入，任何字段命中高敏秘密直接整单阻断，杜绝结构字段绕过。
* **保留令牌字面量守卫**：无论检测器是否返回敏感区间（即使返回空 Span），输入文本包含保留命名空间字面量（如 `<<ENT_...>>`）均严格拦截阻断。

---

## 4. 静态模板免检契约 (Static Exemption Contract)

* **双重边界匹配**：仅对事前经过安全审批登记的静态系统模板免除检测。
* **精确性要求**：必须同时满足内容 100% 精确匹配与字符起止边界精确吻合。任何单字篡改、标点差异、动态变量混入或不可分离的前后缀均使免检失效，强制进入全量检测。

---

## 5. 版本清单生命周期契约 (Version Manifest)

* **原子绑定与深层不可变**：在请求生命周期内，强制绑定一致的规则包、词典、NER 模型与路由配置哈希（`RequestVersionHandle`）。清单内部组件字典强制为只读/深不可变结构，任何试图在运行时清空或修改组件的行为均被阻止。
* **固定路由声明**：完整版本包内声明本请求绑定的服务端固定上游渠道（包括 New API 或直接供应商端点、模型映射及凭据引用），禁止客户端通过请求头或参数指定外部 URL。
* **原子拒载与回滚**：损坏或哈希不匹配的资源包在加载期立即拒绝加载并回滚，保证运行中在途请求与热更新安全隔离。

---

## 6. 出口客户端与凭据隔离规范 (Egress & Credential Isolation)

* **客户端凭据绝对隔离**：网关无条件清除所有入站客户端授权凭据（`Authorization` / `api-key`）及企业内部私有头，禁止向外部或上游透传任何企业认证信息。
* **服务端注入上游凭据**：根据服务端受控配置与路由绑定，由出口客户端生成并注入上游专用的鉴权头（如 OpenAI 规范的 `Authorization: Bearer <upstream_token>`、Claude 规范的 `x-api-key` 与 `anthropic-version`）。
* **上游响应净化与错误断链**：上游返回的 4xx/5xx 错误响应正文一律丢弃，仅保真透传安全的状态码与必要头（如 `Retry-After`），防止供应商在错误回显中泄露已替换或未替换的敏感内容。内部受控异常（`SafetyError`）强制断链，错误信息不回显业务正文。

---

## 7. 审计留证与意图不可篡改规范 (Audit & Intent Integrity)

* **外发前持久放行意图**：外发前必须向持久化介质可靠提交 `ReleaseIntent`，绑定受信请求、租户、保护域、请求模型、上游模型、渠道版本及完整包哈希。
* **单追加不可覆盖**：相同 `intent_id` 的意图记录严禁被后续请求或不同用途覆盖，已存在则强制拒绝。
* **崩溃恢复真实性**：崩溃恢复核对时，若发现损坏（如 0 字节）的裁决记录，严禁判定为已成功，必须标记为 `RESULT_UNKNOWN` 并触发告警。
* **容量水位阻断**：审计日志与留证空间达到政策警戒水位时，直接阻断新外发请求。

---

## 8. 自动知识采集与持久化闭环契约 (Knowledge & Spool Contract)

* **自动生成观察事件**：网关流水线对获准输入自动生成合法的最小知识观察事件（`ObservationEvent`），包含保护域、来源坐标、版本、用途、保留策略与初始受限访问范围，无需上游调用者显式传入事件。
* **加密 Spool 有界队列**：外发前强制将知识观察写入加密持久化队列（Spool），队列对正常事件与缺口记录（GapRecord）统一实施严格的文件数与容量配额限制，杜绝容量击穿。
* **信封多用途强绑定**：加密信封中的保护域、用途及保留桶必须与内部事件严格一致，任何错域或跨用途利用均被丢弃拒收。
* **PostgreSQL 持久化闭环**：独立 worker 消费 Spool 提交至 PostgreSQL 关系库，严格校验实体、关系与来源外键约束；在多方审批发布、Transactional Outbox 幂等消费及下游撤销回执前，知识资产不向外发布或污染在线词典。

---

## 9. 质量审计与置信区间门禁 (Quality Audit)

* **独立数据集无交集**：训练、微调与评估测试集物理隔离，严禁数据穿透。
* **零泄露硬门禁**：对绝密（Secret）级别敏感实体的漏检率要求为零容忍（0 泄露），单例违规一票否决。
* **严格单侧统计上界**：使用严格单侧置信区间检验（如 $3/n$ 法则），确保评估质量达标后方可上线生效。
