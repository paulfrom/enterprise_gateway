# BYOK来源与独立进程持久密钥

供应商凭据只由客户端按请求提供，网关不保存供应商付费Key，不承担模型费用或模型推理算力。供应商协议、地址和模型由服务端固定；无凭据或失败时拒绝，不切换到其他账户、模型或直连出口。

Key持有证明不能转化为企业身份。BYOK入口构造UnverifiedSourceContext，以服务端秘密HMAC关联来源，租户与保护域绑定在服务端。来源可信度为unverified，知识归属为unassigned，ACL限制在域的restricted-candidate处理范围。管理入口使用独立的管理员会话与AdminContext（见ADR 0007），不将客户端头或BYOK凭据升级为管理权限；真实企业身份契约仅保留给既有受信内部流程。

分类由受信服务端分类器取得。客户端自报头不能升级分类；没有分类器、缺失/未知分类、禁止外发分类均拒绝外发。合法BYOK与已装配分类器下，LOCAL_ONLY及未知分类可经过本地检测、加密留证与受限观察沉淀，随后拒绝外发；秘密、协议或存储失败仍拒绝该路径。默认CLI未绑定实际业务分类器，存活不表示可外发。受控测试中的固定分类只验证技术链路，不能代替生产业务政策。分类授权与检测是独立门禁。

部署入口沿用 ASGI/uvicorn 的受信 Python 模块装配模式：运维可用 `module:callable` 指定同步分类函数，程序集成继续使用同一 `build_app`；没有默认获准实现。模块目录属于供应链受信代码，客户端不能指定、上传或替换。入口与供应商上游允许 HTTP/HTTPS，包括非 loopback 地址；传输协议由运维固定配置，不是统一 HTTPS 准入门禁。沿用 httpx 的 URL scheme 选择与 uvicorn 的可选证书参数，不新增豁免开关；HTTPS 使用原生证书对并在启动前校验，上游保留证书/主机名验证，TLS 失败不降级。HTTP 不提供传输加密，两种协议仍执行相同 BYOK、分类、检测、留证与固定出口校验；容器默认端口仅发布到 loopback，公网监听由运维显式决定。

数据库初始化是独立管理操作：仅创建未存在的新 schema，复用当前 SQL 定义，在同一 PostgreSQL 事务执行 DDL、受限授权和 forced RLS；不将管理凭据交给 worker，不改历史 schema，不提供兼容布局或迁移。初始化工具检查应用账号及其可切换角色，既有 worker 继续只消费受限连接。远端生产连接需单独满足 TLS、身份和生命周期治理。

部署初始化与 worker 启动使用同一角色门禁：拒绝超级用户、BYPASSRLS、创建数据库/角色及复制能力，以及 MEMBER 可达的特权角色和任意 `pg_*` 全局预定义角色。预定义文件/程序执行能力不能仅用 rolsuper 标志判断；检查包含 NOINHERIT 下仍能 SET ROLE 的成员关系。专用连接不支持身份切换，要求登录用户、session_user 和 current_user 一致，不能用管理凭据加 role 参数伪装为受限服务连接。worker 另核验全部资产表的 forced RLS，并以 pg_has_role MEMBER 拒绝当前 owner 及其可达成员，不以六张核心表或单个 OID 相等代表完整权限边界。单次 worker 提交失败必须向运维返回非零退出码，不能以保存失败统计代替失败状态。

本地持久密钥后端采用现有KmsProvider接口：运维master key由秘密文件或明确环境配置提供；每个用途/保留桶随机独立生成KEK，其状态经AES-GCM认证加密落盘。OS文件锁与原子持久提交串行化跨进程修改；每次操作重新读取状态，禁止缓存被销毁的KEK。显式初始化与正常读取分开；丢密钥拒绝，销毁写认证tombstone且不能重新provision。

FileKms是受控本地后端。它不声称具有HSM的防提取能力，也不能证明所有备份或旧快照不可恢复。master、目录ACL、备份、恢复及轮转需单独治理；Windows目录fsync沿用现有durable_write能力限制。原始恢复映射仍仅请求内存，审计证据与最小观察事件使用不同用途密钥。

在线服务同步完成原始请求加密留证和观察spool后再外发；独立worker只使用既有本地规则抽取器与PG受限sink，不需要供应商Key。来源、认证加密最小观察及候选在同一PG事务提交后才确认删除spool，保留原始权限、用途、期限与版本以支持复核；没有候选也不丢弃观察。加密或PG失败保留spool，重启/重放通过提交后确认及dedup实现幂等，不自动发布，不声明分布式exactly-once。受限沉淀不代替生产留存、备份删除或知识发布验证。

2026-10-10 补充决策：管理员使用独立会话和专用受限 knowledge PG 登录连接直接治理来源与发布候选。DDL v2 的管理 RLS 同时检查数据库身份、`app.admin_context` 和服务端租户/域；worker/consumer 不因设置同名 GUC 获得管理权。原始 BYOK 来源始终保持 unverified，消费授权单独版本化，撤回和到期通过权威生命周期及失效事件拒绝后续使用，保留原始 ACL 作为证据。

审计正文由管理员直接读取受控后台目录中的单条记录，不再使用申请/双批准/一次性消费链。目录依赖持久化的精确证据关联及服务端生命周期，沿用 FileKMS、AES-GCM/AAD 和 durable_commit；访问尝试与结果留痕，最终会话、读取预算与保留期限复检失败不释放正文。目录构建和治理管理隔离于模型请求，既有同步加密留证和 Spool 门禁不变。
