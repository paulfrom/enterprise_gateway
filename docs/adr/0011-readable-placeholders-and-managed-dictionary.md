# 类型角色占位符与数据库受管词典

## 决策

参考 tuomin 的两遍角色识别、按前缀计数和统一占位符语法，将外发代号改为 `<TYPE_001>`。请求内同类型、同精确原值复用同一标记；超过 999 时继续使用更多位数。已有 HMAC 构造参数仅作为迁移兼容接受，不参与生成，不保留密钥。普通输入和响应中的旧 `<<ENT...` 命名空间仍拒绝。

组织和供应商实体根据明确的邻近合同或投资线索分配角色。先汇总整个请求的角色证据，再替换全部片段，允许后出现的角色声明影响前面的提及。冲突角色退回原实体类型；不采用最后线索覆盖，不把个人实体自动赋为机构交易角色。

类型/角色与编号保留语义，不证明模型推理正确。不同请求或文件中相同编号不代表同一实体。全称、简称及空白差异保留独立的精确原值映射。恢复表只存在请求或文件内存；未知、可识别损坏、冒充或结构字段中的标记继续拒绝。

## 词典持久化

PostgreSQL 中的独立词典表是实体文本、类型和启用状态的权威来源。恢复映射不入库。现有受控 JSON 只在作用域首次初始化时导入；已有发布版本后不再读取种子文件。

管理会话在部署 tenant/domain 内编辑草稿，全部写入携带期望修订号。保存、停用和删除只改变草稿。发布编译成功并构造完整新装配后，事务提交不可变版本及活动指针；失败保留原发布版本。版本表拒绝服务登录的修改和删除。

新模型请求及文件请求先读取发布修订号。发生更新时替换完整流水线、风险筛选和文件检测快照，复用原 NER 执行资源和出口客户端；已捕获旧对象的请求完成旧版本处理。数据库失败拒绝新处理，不使用文件或旧缓存旁路。

## 边界

字典词条、快照和变更元数据受管理登录及 forced RLS 保护，处理域来自服务端。客户端不能指定 tenant/domain、政策、检测器或原值恢复表。管理接口执行已有会话、同源、CSRF、限额及交付前会话校验，不记录词条正文、搜索条件或请求正文摘要。

请求历史、审计证据和 Spool 保留既有 AES-GCM 信封加密。来源关联、会话证明等其他密码学用途独立于占位符编号。

新增表、约束、RLS 和不可变触发器由部署方手工执行 v4 增量 SQL；服务和测试只验证已有对象并执行普通 DML，不创建基础设施或修改授权。
