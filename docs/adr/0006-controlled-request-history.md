# 四阶段请求历史与知识资产分离

用户需要通过网页查询四阶段正文，并明确不用账号系统、直接查询当前网关全部历史。独立请求记录使用网关级查询凭据和有期限的加密存储，不从供应商Key推定身份、来源所有权或知识阅读权限；持有查询凭据即拥有全部请求历史读取范围，网页遮挡仅是交互措施。

恢复映射对象仍仅在当次请求内存使用，但完整四阶段正文可能推断出原值对应关系。为提供历史对照而明确接受这一新增受控留存面，不再声称“不保存映射表”能排除重建关系；记录不得用于跨请求在线恢复，不开放知识观察原文或原审计双人审批接口。

沿用既有PostgreSQL、AES-GCM信封加密和同步留证模式，使用独立namespace和必填留存政策，避免把完整调用历史混入知识表、普通观测或外部遥测平台。失去必需历史持久化资源时拒绝继续，流式结果保留实际片段而不补造完整响应。在线删除不等于已证明所有备份的密码学销毁。
