# 四阶段请求历史与知识资产分离

用户需要通过网页查询四阶段正文，并明确管理员直接查询当前网关全部历史、不使用独立查询Key。历史读取经管理员会话（AdminContext，见ADR 0007）授权，不从供应商Key推定身份、来源所有权或知识阅读权限；管理员会话即拥有本服务管理范围内全部请求历史读取范围，页面不再以遮挡开关作为原文可读条件。

恢复映射对象仍仅在当次请求内存使用，但完整四阶段正文可能推断出原值对应关系。为提供历史对照而明确接受这一新增受控留存面，不再声称“不保存映射表”能排除重建关系；记录不得用于跨请求在线恢复。审计原文读取由管理员直接审阅替代旧双人审批工单（见contracts/admin-record-review.md），不开放知识观察原文的匿名接口。

沿用既有PostgreSQL、AES-GCM信封加密和同步留证模式，使用独立namespace和必填留存政策，避免把完整调用历史混入知识表、普通观测或外部遥测平台。失去必需历史持久化资源时拒绝继续，流式结果保留实际片段而不补造完整响应。在线删除不等于已证明所有备份的密码学销毁。
