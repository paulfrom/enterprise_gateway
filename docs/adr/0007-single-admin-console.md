# 单管理员控制台与管理授权

管理端只供管理员使用，当前只有一个固定账号 admin。管理员经真实登录页由服务端验证凭据后建立服务端会话，浏览器仅以 HttpOnly/SameSite=Strict Cookie 携带不透明会话令牌；服务端保存令牌摘要、固定空闲期限30分钟、绝对期限8小时，退出即持久注销。会话产生不可由客户端构造的 AdminContext（actor=admin、部署管理范围、会话关联摘要、认证与到期时间），全部管理 API 经统一管理员依赖逐请求校验；会话存储失效时管理 API 拒绝，不降级到任何旧查询 Key。

admin 在本服务管理范围内拥有全部管理动作权限：查看全部历史与四阶段正文、受限观察、候选、发布与撤回记录，并直接执行来源治理授权、验证发布、拒绝、修订、撤回、配置发布/回退、审计直接审阅、留存清理与维护作业。取消知识发布和审计原文读取的双人审批、第二角色、工单申请与自批禁止；确认授权、验证和发布可由同一 admin 一次提交原子记录，这是直接管理动作而非第二人审批。详细认证、会话、CSRF 与路由契约见 contracts/admin-console.md。

管理员授权与业务权限严格分离：管理员会话不替代模型 BYOK，不传给供应商，不参与来源 HMAC 或计费；管理登录不自动把 unassigned 改为 admin 所有，也不把 unverified 改为 verified，知识所有权、原始来源 ACL、处理 ACL 与下游消费授权分别保留。来源治理授权与事实验证形成新版本记录，原始 ACL 与原始证据不原位改写。

管理数据库访问使用专用受限 PG 应用连接（非 owner、无 BYPASSRLS），管理 RLS 分支同时绑定专用管理数据库身份、服务端 AdminContext 和本部署租户/域，worker/consumer 身份不能 SET ROLE 到管理身份。新 DDL 删除旧审批表与身份触发器，首次上线使用新的隔离 schema/实例，不写 migration，不自动搬运旧数据；旧 schema 无法与新管理服务混用，启动给出固定净化错误并拒绝相应能力。
