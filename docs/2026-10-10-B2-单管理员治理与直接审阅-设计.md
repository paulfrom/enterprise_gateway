# B2 单管理员治理与直接审阅 — 设计文档

日期：2026-10-10。前置：B0（契约基线 #3）、B1（登录与历史贯通 #4）已合并。
上游依据：`docs/2026-10-09-管理员登录与全能力管理实施计划.md` §12 B2 行、§12.1 文件所有权、`docs/contracts/admin-console.md`、`docs/contracts/admin-record-review.md`、ADR 0007。
本文是 B2 批次的实施设计；正式任务书与 WBS 登记由 root 在开工时建立。

## 0. 已裁决的边界问题

1. **纯后端批次**：B2 不触碰 `web/**`，管理页面全覆盖归 B4。纵切为真实 PG + HTTP/TestClient 级。
2. **record_review.py 整文件删除**：`audit/record_review.py` 与 `tests/audit/test_record_review.py` 删除，直接审阅由 `audit/admin_reader.py` 全新实现。计划 §10.2.3「不删除旧审批文件」仅指数据库对象与数据，Python 模块不属于该豁免。
3. **审计目录用文件存储**：可信审计目录为 durable_commit 文件目录，audit 保持零新增 PG 依赖，出口路径零新依赖。
4. **五任务纵切**：T1 DDL/存储 → T2 治理服务 → T3 audit reader → T4 管理 API 整合 → T5 集成纵切。
5. **范围裁剪**：`publications/export`、`dictionary/compile`、`retention`、`maintenance`、`jobs` 契约路由**不属于 B2**（前两者的归属在 B4 前后治理增强批次再定，后三者归 B3）。

## 1. 数据层：DDL v2

同一配置 namespace，替换式新结构；不写 migration，不对旧 schema 自动 ALTER/DROP，不搬运数据。

### 1.1 删除的旧双人构件

- `knowledge_approvals` 表（角色 CHECK）、`enforce_reviewer_identity` 触发器
- `enforce_publication_admission` 的 `approval_count<>2` 人数准入（触发器位置保留，语义重写，见 1.3）
- `save_approval` 及发布前置审批数复查、reject 的角色检查

### 1.2 新增/改造对象

| 对象 | 变更 | 契约要点 |
|---|---|---|
| `knowledge_admin_actions` | 新增 | 单管理员验证/动作记录。列：admin_action_id(uuid pk)、actor_id（服务端固定 admin）、session_digest（会话关联摘要）、action_type（CHECK 枚举：governance_confirm/publish/reject/revise/withdraw/revoke/audit_read）、object_type+object_id、object_version、rationale（依据）、intended_use、consumer_audiences(text[])、result(succeeded/failed)、created_at。承载「至少绑定 admin 主体、对象版本、动作、用途、消费受众、依据、时间、结果」 |
| `knowledge_governance_versions` | 新增 | 来源治理版本。列：governance_version_id(uuid pk)、source_id+source_version、admin_action_id FK、ownership/confirmed 归属、intended_use、consumer_audiences、validity（期限）、rationale、created_at。确认产生新版本；sources 原始行（原文/证据/原始 ACL/unverified 可信度）**不原位改写** |
| `knowledge_publications` | 改造 | publish 事务 INSERT 绑 admin_action_id + 当前有效 governance_version_id |
| `invalidate_knowledge_source`（SECURITY DEFINER） | 保留语义 | 撤回级联：tombstone+outbox、consumer_assets 失效、来源 ACL 清空 |
| `read_authorized_knowledge_candidate`（SECURITY DEFINER） | 保留语义 | 消费者逐行授权读；消费者不扩权的根基 |
| 全表 RLS | 保留 ENABLE+FORCE | 策略分身份分支，见 §2 |

### 1.3 发布准入触发器（重写）

`enforce_publication_admission` 新语义：同一事务内存在匹配的 `knowledge_admin_actions` 行（action_type='publish'、object 指向该候选、result='succeeded'）且来源未失效、当前治理版本有效。人数检查彻底删除；失败不得伪造已发布。

### 1.4 结构指纹与旧 schema 拒绝

- `SCHEMA_FINGERPRINT_V2` 代码常量：对 schema 内表/列/函数/触发器/策略的 pg 元数据做规范化 canonical JSON 后 sha256；不对 DDL 文本哈希（避免格式脆弱）。T1 首次实现时由真实计算产生并内嵌，随后任何结构变更必须同步更新常量。
- 管理连接与 knowledge worker 启动均校验指纹；不匹配 → 固定净化错误 `KNOWLEDGE_SCHEMA_INCOMPATIBLE`，管理能力拒绝、worker 拒跑；零自动修复、零数据变更。旧 v1 实例保持原样独立运行。
- 初始化器 `scripts/prepare_knowledge_database.py` 延续「拒绝已存在 namespace」；事务内建 schema + v2 DDL + 双角色授权 + 回读校验（forced RLS、非属主、无 SET ROLE 路径、表/函数/触发器/策略全契约——不能仅检查固定 13 张表）。

## 2. 管理连接与 RLS 模型

契约要求管理 RLS 分支绑定**专用管理数据库身份**；history 侧运行时的单连接三 GUC 模式不满足，B2 新建双连接模型：

- **管理连接**：gateway 进程内为管理 API 建立第二条 PG 连接。新 secret `GATEWAY_ADMIN_KNOWLEDGE_PG_DSN(_FILE)`（exactly-one，镜像 `_history_spec` 校验模式），DSN 的 `search_path` 绑定 knowledge schema，连接角色 = 专用受限管理角色（非 owner、非 superuser、非 BYPASSRLS）。
- **AdminContext 注入**：每事务 `SET LOCAL knowledge.tenant/domain/admin_context=true`；值由服务端从有效管理会话的 AdminContext 注入，**不接受任何请求参数**。`current_user` 即连接角色，客户端身份头与 `SET LOCAL` 伪造路径天然免疫（反例测试证明）。
- **管理策略**：`current_user = 管理角色 AND admin_context AND tenant/domain 匹配部署`。管理读取**不看消费者 active publication 过滤、不看来源 ACL**（admin 可查受限/拒绝/撤回/到期元数据）；正文释放走服务端解密路径，守实际保留与密钥状态，SQL 层不放开密文直读。
- **部署门禁**：prepare 回读 `pg_auth_members` 证明 worker/consumer 角色无到达管理角色的成员路径；`database_security.py` 扩展对应断言供 worker 启动复检。

## 3. 治理服务 v2（`knowledge/governance.py` 重写）

每个动作 = 一条事务：INSERT `knowledge_admin_actions` → 业务变更 → outbox，三者原子。

| 方法 | 语义 |
|---|---|
| `confirm_source_governance(source_id, *, use, audiences, validity, basis, context)` | 校验来源存在且未撤回 → admin action → 新 governance_version。原始来源行不动 |
| `publish_candidate(candidate_id, *, basis, context)` | 准入：证据实际存在、非纯共现/纯模型自证、来源未失效/未过期、**当前有效治理版本**（不因原始 unverified 永久禁止已完成合法验证的数据）。publications+outbox 同事务绑 action+governance_version。失败返回明确业务错误，不伪装成「缺另一人批准」，不伪造已发布 |
| `reject_candidate(candidate_id, *, basis, context)` | 拒绝置状态 + action 记录 |
| `revise_candidate(candidate_id, *, modifications, basis, context)` | 生成**新 candidate 版本**（derived_from 旧版）；旧证据不原位改写、不伪造来源 |
| `withdraw_source(source_id, *, basis, context)` | `invalidate_knowledge_source` 级联（tombstone/outbox/consumer_assets 失效/ACL 清空），入口绑 admin action |
| `revoke_publication(publication_id, *, basis, context)` | `revoke_transactional` 语义保留，steward 角色检查换 admin action 绑定 |

- admin 路径**禁用内存 dict 回退**（管理必须真 PG）；`KnowledgeLedger` 内存实现仅保留给 extractor/consumer 纯单测。
- 消费者侧（`GovernedConsumer`、`active_publication_ids`、逐行 savepoint 授权读）语义零改动；B2 不把消费循环接入 worker 主循环（现状本未接入），「消费者不扩权」由 T5 集成测试在新 DDL 下证明。

## 4. 审计直接读取（`audit/admin_reader.py` 新文件）

### 4.1 可信审计目录

- state 下新目录 `audit-catalog`，durable_commit 原子写（沿用 `audit_intent` 模式，OS 锁+配额）。
- `evidence_gate` granted 时追加 `CatalogEntry`：record_id、purpose、domain、bucket、intent_id、evidence_path、evidence_sha256、bytes、created_at、status(available)。
- **崩溃窗 fail-closed**：catalog 有而 evidence 缺失或 sha256 不符 → 条目按 corrupted 拒绝释放正文；evidence 有而 catalog 无 → 该记录对管理读不可见（不接收任意密文/路径）。

### 4.2 AdminReviewService

gateway 只注入 `FileKmsProvider`（与 history 共用 KEK 持有链，不自建 KMS）。

- `list_records(filters, cursor)`：目录分页（服务层内存排序过滤）；`get_record(record_id)`：仅元数据。
- `read_plaintext(record_id, context)`：条目存在/未过期 → AAD 匹配校验（domain/purpose/record_id，与 `envelope_crypto.build_aad` 一致）→ `decrypt_record` 解密 → **访问留痕 durable_commit**（actor、session_digest、record_id、purpose、时间、真实结果）→ 释放明文。任一环失败不释放正文；**留痕写失败 = 关键审计失败 = 不释放正文**。
- 会话到期控制：API 层释放前 `auth_service.revalidate`（B1 `history_api` 先例）。

## 5. 管理 API 整合（认证/装配 worker）

新文件 `gateway/admin_knowledge_api.py`、`gateway/admin_audit_api.py`；模式沿用 `install_history_routes(app, store, auth_service)`：每域一个 `install_*_routes`，在 `create_app` 同一装配点挂载。

- **管理查询**：`GET /api/admin/observations|sources|candidates|publications` 及对应详情（全状态；不用消费者 active 过滤）。
- **治理动作**（写路由，同源+CSRF）：`POST /api/admin/sources/{id}/governance`、`/candidates/{id}/publish|reject|revise`、`/sources/{id}/withdraw`、`/publications/{id}/revoke`。
- **审计读取**：`GET /api/admin/audit/records|/{id}|/events`。
- `_write_dependency` 从 `admin_api.py` 私有提升为模块级公共依赖（同 owner，无所有权交叉）；`ADMIN_ERROR_CODES` 扩展 `KNOWLEDGE_*`、`AUDIT_*`、`KNOWLEDGE_SCHEMA_INCOMPATIBLE` 等固定码（错误语义沿用契约 §4：401/403/404/409/422/503）。
- 装配：`start_gateway.py` 新增 `_admin_knowledge_spec()`；未配置 admin DSN 时知识/审计管理路由返回 503 真实状态（对缺资源给真实状态，不开放任何绕过）。
- 正文释放前一律 revalidate；写路由全部经过统一管理员依赖。

## 9. 风险

1. **指纹常量与 DDL 漂移**：DDL 改了常量没更新 → 启动即拒。缓解：T1 测试强制「常量 = 真实元数据计算值」。
2. **T4 的 `app.py`/`start_gateway.py` 与 T5 读依赖**：顺序执行规避；冻结点在任务间固化接口。
3. **evidence_gate 追加目录的非原子窗**：§4.1 fail-closed 规则覆盖；T3 用损坏注入测试证明。
